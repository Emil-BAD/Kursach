# Быстрый старт

Ниже — рабочая инструкция по запуску проекта в локальной среде разработки. Проект представляет собой backend-платформу для управления общежитием на FastAPI и SQLAlchemy, поэтому локальный запуск позволяет быстро проверять API, роли, сценарии доступа и доменные модули.

## 1. Требования

Перед запуском убедитесь, что у вас установлены:

- Python 3.11+
- pip
- Git
- PostgreSQL (или рабочая локальная БД, если проект запущен в соответствующей конфигурации)

## 2. Клонирование репозитория

```bash
git clone <repository-url>
cd Kursach
```

## 3. Создание виртуального окружения

### Windows (PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### Linux / macOS

```bash
python -m venv .venv
source .venv/bin/activate
```

## 4. Установка зависимостей

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## 5. Конфигурация окружения

Скопируйте пример файла окружения:

```bash
copy .env.example .env
```

Проверьте значения переменных, особенно:

- `DATABASE_URL`
- `SECRET_KEY`
- `CORS_ORIGINS`
- `ACCESS_TOKEN_EXPIRE_MINUTES`

Пример настройки:

```env
SECRET_KEY=your-secret-key
DATABASE_URL=postgresql://user:password@localhost:5432/dormitory_db
CORS_ORIGINS=http://localhost:3000,http://127.0.0.1:3000
ACCESS_TOKEN_EXPIRE_MINUTES=15
```

## 6. Запуск приложения

```bash
uvicorn api.app:app --reload --host 0.0.0.0 --port 8000
```

После запуска сервис будет доступен по адресам:

- API: http://127.0.0.1:8000
- Swagger: http://127.0.0.1:8000/api/docs
- Redoc: http://127.0.0.1:8000/api/redoc

## 7. Проверка работоспособности

Можно проверить базовый статус через браузер или curl:

```bash
curl http://127.0.0.1:8000/api/docs
```

Или через Python-проверку подключения:

```bash
python -c "import requests; print(requests.get('http://127.0.0.1:8000').status_code)"
```

## 8. Основные сценарии после запуска

### Авторизация

Система использует JWT, поэтому для большинства операций потребуется Bearer token.

### Администрирование

Роли и доступы определяются через RBAC. Для административных действий используются специальные права и проверки в зависимости от доменного модуля.

### Модули системы

После запуска можно тестировать:

- маршруты пользователей
- новости и события
- проверки чистоты
- платежи и счета
- сервисные запросы
- административные сценарии

## 10. Рекомендации по разработке

- не смешивайте бизнес-логику в роутерах
- используйте строго разделение на repository / service / router
- нормализуйте ошибки через `api/core/exceptions.py`
- работайте через RBAC вместо ручных проверок по идентификаторам ролей
- держите доменные сущности и API-схемы отдельно

## 11. Частые проблемы

### Проблема: приложение не запускается

Проверьте:

- установлен ли Python 3.11+
- активировано ли виртуальное окружение
- заполнены ли переменные в `.env`
- доступна ли база данных

### Проблема: 401 или 403

Проверьте:

- корректность JWT токена
- наличие нужной роли и прав
- правильность заголовка `Authorization: Bearer ...`

### Проблема: ошибка с БД

Проверьте:

- корректный `DATABASE_URL`
- существование базы данных
- миграции или инициализацию схемы
